# 修理铺布景与背景调度：可运行正反案例

这是**局部布景教学案例**，不是完整影视城、正式作品或最终 AI 画面。用于识别“体块草稿”和“指定机位有可读结构”的差别。全剧世界仍按 [影视城标准](../../doc/virtual-studio-library-design.md) 建设路网、街坊、生活配套和远景；本例相邻楼仅外景代理，不能用它替代全城或拍邻楼室内。

所有图片与视频均由本目录三维文件经系统实际 Three.js 渲染器拍出，没有使用图像模型伪造模型验收。模型为本仓库原创示例，可随项目复用。内容生成脚本与模型可以由制作 Agent 在自己的作品目录修改，系统源码只读。

## 同机位正反对照

| 检查 | 体块草稿（不满足本用途） | 已准备结构（只适用于下列范围） |
| --- | --- | --- |
| 工作台中景 | [反例](workshop-blockout.png)：工具只有方块，缺少实际用途 | [正例](workshop-prepared.png)：台面高度0.95米；螺丝刀的柄与杆、开口扳手、钳子、台钳、灯与电池可辨；不代表手指操作已验证 |
| 街边与店内关系 | [反例](street-blockout.png)：环境没有背景活动，道具未具备辨识结构 | [正例](street-prepared.png)：门窗有实际开口，店内外连通，自行车有车架/轮辐/车把/坐垫，背景人物归场次而非固定场景 |
| 内向外反打 | 不可以只验正面 | [反向检查](reverse-prepared.png)：同一门窗外仍是同一道路与对面门面；其他未拍方向不宣称合格 |

不要照搬模型数量、机位坐标或群演人数。正例也有边界：没有主角手指/IK、没有真正修灯动画、相邻门面不支持进入、没有整城远景。工具细节用于本例中景结构辨识，特写应按真实形状进一步建模和检查。灰色材质只表示空间，不要求最终写实图复制灰模材质。

轮胎接地是硬要求：本例修正了遗漏18厘米人行道顶面造成的埋地错误，建模脚本现在用实际轮胎几何最低点对齐支撑面并断言。不能把模型原点为0当作接地；该断言仅覆盖本例自行车的平面接触，不是通用碰撞检测。此前版本的接地检查不成立，以当前模型指纹和重拍图为准。

## 群演调度与切镜

[16秒真实背景预演](background-motion.mp4)包含两个8秒镜头。它是本地三维预演，**不能直接当单次H3输入**；最终生成仍按单元容量拆分，当前指定H3最多14秒。

**2026-10-27 渲染v2复验**：本例已使用统一接地骨架重拍。完整两镜背景动作进行了962个动态网格采样，未发现所查范围内的接地或穿透问题；实看静帧与动态承接。旧版悬空/蹲姿埋地问题已修，历史画面不再作为当前证据。仍只展示局部布景、粗略步态和位置承接，不代表精细表演或整城合格；查看[当前动作规范](../../doc/virtual-production.md#动作控制与接触检查)及inspection.json的具体范围。

- `bg-walker` 在人行道由西向东行走，速度0.8米/秒。第一镜末与第二镜初位置都为 `[-3.6,0.18,5]`，切镜保持身份和路线，不能各镜重新从入口出现。
- `bg-neighbor` 在长椅附近等候，`bg-shopkeeper` 在相邻店铺门口留守；没有给静止人偶冒称“收摊表演”。
- 三者都是 `performanceRole:background`，`activity` 说明用途，不伪造主角资产或要求全套人物资料板。
- `frames.states` 是唯一的位置/朝向/姿态/可见性时间数据；本例不另建群演时间线。有网格与支撑检查但没有自动导航/刚体求解，修改路线仍须实看穿墙、相撞、遮挡、滑步与切点。
- 本例是白天有人经过的街边。空巷、停业或剧情需要孤寂时可以无人，不为“丰富”机械增加群演。

## 数据和使用方法

[case.json](case.json)含 `preparedWorld`、`blockoutWorld`、`plan`、`scene`、检查机位和资源清单；[build.ts](build.ts)展示在作品目录创建内容的方法。它不读写项目数据库。两个GLB分别为 [准备后的结构](prepared.glb) 和 [体块反例](blockout.glb)。反例不用于正式下游生成。

远程 Agent 先 `GET /api/operator/documents/production-examples`，按返回的 `files` 下载：`GET /api/operator/documents/production-examples/files/文件名`。这里只开放固定案例文件，不暴露作品目录或密钥；无需UI即可读取原生JSON、GLB和真实PNG/MP4。

将局部案例用于作品时：

1. 读已有世界、正式镜头和当前版本，确认本片段用途，勿覆盖整城。
2. 通过3D模型库上传GLB，以返回的真实模型ID和清单替换示例modelId/URL。案例中的资源地址只用于案例预览，未上传不能直接保存到作品。
3. 在已有地点加入所需组件，映射物体/地点ID；不复制 `example-*` 作为已有作品ID，不替换原街区。镜头使用作品真实shotId/时长，不为了案例改成8秒。
4. 用现有场次保存接口携带世界、分集与拍摄版本，保存背景对象和关键帧。确认门窗、入口、邻楼方向与本剧一致。
5. 按项目制作约定粗看本用途的代表画面；仅动态用途查看相关预演，不为静态构图额外拍整段动作。明显大问题在约定返工范围内修模型或调度，超过上限交作者精审，不反复重拍。不要修改系统渲染器，不把示例截图登记为本作品实拍证据。

## 维护与验证

维护任务可运行 `node --import tsx examples/virtual-production/build.ts` 重建本例数据，再运行 `node --import tsx tests/production-examples-capture.ts` 重拍。后者只启动本机临时预览，使用真实空间渲染器，不连接作品数据库或供应商。

[inspection.json](inspection.json)记录文件指纹、几何量、设备、分辨率、短路线性能及检查范围。渲染成功只生成待检查记录；必须打开对应图片并查看动态预演后才记录具体视觉结论。此性能样本不代表整座影视城或其他设备。
