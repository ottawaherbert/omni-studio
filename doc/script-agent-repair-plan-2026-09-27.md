## 目标与边界

作者使用同一剧本专家助手。手动模式由作者决定每一步；Agent 模式接收目标后，通过共用工具规划、写正文、检查、有限返修，交付一集或电影的工作稿。聊天、快捷操作、Agent 是同一能力的入口。正式作者稿只经比较采用改变；暂停、作者接管、修改目标、重新继续均保留既有证据和成果。

计划覆盖已确认的七项缺口和长链执行效率。不能用新增表单或改一套视觉交互代替接通流程，也不能放宽授权、删除历史或关闭来源核验来使测试通过。

## 实施方案

1. **统一入口与聊天派发**：首页 Agent 不再调用旧的一次性蓝图生成。直接建立持久 Goal 与独立工作稿，保留原输入、对话和 Skill；在现有页面展示进度、问题和成果。作品内自由对话按作者意图派发写作、检查/返修或完整委托；有歧义时询问，不默认为扩大修改范围。显式采用仍保留作者比较确认。
2. **接通作者决定**：将 ASK 的问题、选项与决策身份投影给页面；作者回答绑定当前 Goal/Run/决策和版本，重复提交幂等，过期回答拒绝；回答进入下一次实际决策上下文。普通继续不伪造回答。修订提交作者修改的目标、Skill、执行方式及明确范围，保留旧配置追溯。
3. **准确的新集范围**：续写下一集时，新集是写目标，前集为固定版本只读来源；当前集不自动得到写权限。共用服务端命令组装与权限校验。已有稿件和局部编辑继续遵守选定范围。
4. **前集记忆投影**：仅允许所选固定版本、所选单元及完全对应正文范围的派生记忆进入任务；新工作稿、跨工作稿来源均按来源链验证。不同作品、版本改动、未选单元和撤回来源不能被借机引入；读权限不变为写权限。
5. **有界长对话上下文**：持久保留全部原文，将当前输入、近期有效回合、可追溯的较早历史索引/按需读取分开。失败输入不作为永久必需历史。预算在模型调用前检查，单条过长可明确报错，但随后短消息必须恢复；不静默截断当前输入或 Skill，不把索引当摘要事实。
6. **长链效率**：测量实际宿主、SQLite、检查回执与递归来源核验。改进重复解析和同一有效快照内的重复校验，分批/分页读取；缓存必须受数据库版本、权限、撤回、来源变化和时效约束。保留检查完整性、幂等、租约与预算保护。
7. **整体验收**：在隔离 SQLite/API/真实页面走首页想法→完整委托→ASK→回答→正文→审阅返修→采用→固定导出→重开，以及下一集和暂停接管继续。外部模型需求统一由指定 GPT-6 Sol 子 Agent 生成明确标识的模拟返回；机械协议反例不评价创作质量。每项完成须有实现、实际测试和独立复核。
