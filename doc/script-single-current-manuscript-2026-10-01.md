# 剧本只保留当前稿

2026-10-01 用户要求：删除作品版本功能及其代码。此前方案中关于作者历史版本、另存版本和恢复旧稿的设计，以本说明为准。

## 产品行为

- 每部作品只有一份可编辑的当前稿；蓝图、大纲、分场和正文编辑自动保存到同一份作品。
- AI 返回先作为候选或任务成果供作者审阅，采用后更新当前稿。任务工作内容不构成作者可切换的作品版本。
- 不再提供作品版本编号、历史列表、旧稿浏览、恢复、历史导出及多份本机草稿管理。
- 保存失败时保留一份本机恢复稿；冲突时停止覆盖，保留输入并提示处理。正常创作不要求作者另存或维护版本。

## 影响范围与替代依据

| 原依赖 | 当前处理 |
| --- | --- |
| 作者保存时写入全稿历史 | 仅更新 `script_projects` 当前稿 |
| 作者历史组件、客户端方法和 HTTP 接口 | 删除；导出读取当前稿，文件名不带版本号 |
| 旧 Agent 工作草稿历史与同步前草稿浏览 | 删除；工作草稿仍有一份当前任务内容 |
| 审阅时原文 | 按任务标识读取冻结输入，继续执行上下文可见性检查 |
| Agent 同步、合并 | 每个 Run 或工作空间持有明确的作者输入基线，随同步或采用更新 |
| 已绑定的前文、交互场景、制片筹备引用 | 保留引用发生时的内部输入快照，避免之后的编辑混入已经冻结的任务 |
| 保存与采用并发 | 保留内部 CAS 修改戳，拒绝旧请求覆盖新内容；重复采用返回当前稿 |
| 保存回执期间继续编辑 | 串行保存并保留后续输入；采用后对非重叠修改做三方合并，同处冲突暂停保存 |

采用预览前冻结作者输入，并与待确认采用回执一起保存；恢复回执时使用这份明确基线。预览或采用请求等待期间的输入属于后续修改，不能倒算进采用基线。旧回执没有明确基线时只使用已知保存依据，无法确认则保留本机输入并停止覆盖。

`ScriptProject.revision` 是内部 CAS 修改戳，不是作品版本。通用 `ResourceRef.version`、AI 执行检查点、授权与任务状态戳、Skill 版本以及交付协议版本也不属于作者版本功能，不能为了消除同名字段而删除其一致性或授权校验。

## 既有数据兼容

新库不创建 `script_revisions`、`script_agent_draft_revisions`，新保存也不写这些表。已有旧表只为既有任务输入和固定引用进行条件读取；不导入整套历史，不提供历史访问接口，不自动清空旧库。

本机旧缓存仅作为一次性恢复材料处理：去除相同内容，保留有独有输入的材料；确认处理只登记其原始字节摘要，不擅自删除。新编辑使用每作品一个恢复槽及精确缓存比对，不继续创建页面草稿分支。

本次开发与验证使用内存或临时数据库，不操作真实作品；保留此前未提交修改，不自动提交。
