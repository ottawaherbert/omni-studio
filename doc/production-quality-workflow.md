# 制作质量检查与正式交付

更新：2026-11-03。当前固定阶段和字段以 [领域合同](../packages/domain/src/productionQuality.ts) 为准，服务行为见 [质量服务](../src/server/productionQuality.ts) 和 [HTTP 入口](../src/server/routes/productionQualityRoutes.ts)。本规则用于普通影视制作及按需选择的3D制作，不要求启用严格批量 artifact 管线。

## 责任与推进

总导演承担全局创作责任：确定全剧意图与视听方向，判断整场和整集是否表达了剧情，汇合各专业结论。制片统筹负责当前范围、依赖、资源、制作约定、有限检查/返工次数与交接，不能用排队成功代替质量通过。导演、摄影、灯光、美术、道具、表演、声音、剪辑、场记及副导演/群演协调按实际需要执行本专业设计与检查。

这些职责可以由同一人或一个外部 Agent 兼任，不内置自治多 Agent，不要求分别开会或提交部门审批。8个阶段是工作与质量依赖，不等于8次请用户批准。已有用户授权和制作暂用约定继续有效；作者最终精审不能由 Agent 冒称完成。

## 先总体、再拆分、再总体

| 阶段 | 检查实际对象 | 责任视角与依赖 |
| --- | --- | --- |
| `project_plan` 全剧总体方案 | 故事目标、视觉与声音方向、制作范围和职责 | 总导演；先保存全局责任 |
| `scene_plan` 整场设计 | 本场完整剧本、导演意图、空间与人物、事件前后状态 | 总导演；全剧总体通过后进行 |
| `shot_plan` 拆镜与制作单元 | 剧情覆盖、各镜作用、动作对白估时和切点 | 导演、摄影、剪辑；整场设计通过后拆分 |
| `preparation` 资产、布景与调度 | 身份、服装道具、空间、群演和当前组调度；3D按需 | 美术、副导演、群演协调；拆镜通过后落实 |
| `visuals` 整组画面总检 | 当前实际采用图、宫格或构图图，按顺序核对空间、身份和事件状态 | 总导演、摄影、场记；制作准备通过后进行 |
| `segments` 视频与声音质检 | 当前实际视频、动作表演、相邻边界、对白与声音 | 导演、场记、声音；整组画面通过后进行 |
| `scene_cut` 整场合成总检 | 完整观看、听审本场实际合成视频，核对缺戏、节奏和声画 | 总导演、剪辑、声音；视频声音通过后总检 |
| `episode_cut` 整集总检与交付 | 完整观看、听审本集实际成片，核对必需场次与跨场承接 | 总导演；本集各场合成总检通过后进行 |

严查当前阶段；未检查、未通过或来源已变化，都不能进入依赖它的下一流程。可以继续保存和修订草稿、保留失败候选、探索无关范围，不能把保存成功当放行。普通制作无需3D，`spatialMode:"scene_plan"` 保留普通场面设计；选择 `previs` 时须有实际世界和本场调度，并在生成中实际发送本镜对应构图参考。动态用途检查相应运动过程，静态用途不强制动态预演。

整组检查可用 `shotIds` 指定真实镜头范围；省略时准备/画面检查包含当前镜头及剪辑仍使用的归档镜头，`segments` 按实际剪辑使用的源镜头检查。归档镜头的图与宫格从原记录读取，不必恢复成新镜头。各镜合格不能代替整场和整集观看。视频生成必须实际使用 `visuals` 已审画面，不能在通过后换入未经核对的独立参考；具体媒体用途和模型容量仍按生成能力合同执行。

## API 与实际检查

UI 使用 `Q=/api/production/quality`，外部 Agent 使用 `Q=/api/operator/quality`，后者遵守部署的 Operator 身份和项目访问限制。两者共用质量服务；review 身份分别为 `creator` 与 `external_agent`，不能互相冒称。

| 操作 | 请求与响应 |
| --- | --- |
| 当前状态 | `GET Q/status?target=<JSON>`，target为 `{projectId,episodeId?,sceneId?,shotIds?}`；返回责任、阶段状态、具体阻塞和检查项。只读，不调用模型或自动检查 |
| 保存责任 | `PUT Q/projects/:id/responsibility`，body `{director,coordinator,intent,visualDirection,spatialMode:"scene_plan"|"previs"}`；同一姓名可以兼任 |
| 冻结检查对象 | `POST Q/inspections {target,stage,evidence?}` → `{inspection}`；保存当前实际内容 snapshot 与媒体证据，不自动判通过 |
| 回读对象 | `GET Q/inspections/:id` → `{inspection}`；查看被冻结的业务对象与实际媒体 |
| 提交实际结论 | `POST Q/inspections/:id/review {verdict:"passed"|"failed",findings:[{check,passed,note}],reviewerName}` → `{inspection}` |
| 正式交付 | `POST Q/deliveries {inspectionId}`；整集用当前已通过的 `episode_cut`，整场交付用 `scene_cut`，返回该次实际已总检视频 |

每次 inspection 冻结当前实际内容和媒体，检查责任人须读 snapshot、查看实际图像、播放视频、听审声音。`findings` 须覆盖该阶段所有检查项，逐项显式填写 `passed:true|false` 与实际观察 `note`，不得默认勾选、只写“全部通过”或伪造看听记录。总体阶段填写总导演姓名；专业阶段填写实际检查人姓名。

`evidence` 是 `[{mediaUrl,mediaKind:"image"|"video"|"audio",shotIds?,note?}]`。`visuals/segments` 省略时由服务读取当前采用媒体；指定范围要真实对应镜头，服务核对媒体字节与本镜当前选用成果。segments包含当前未静音的独立声音，视频须覆盖选定的源入点和时长，不能用另一镜素材或静图占位替代。`scene_cut/episode_cut` 必须提交一份实际整场/整集视频，不能以单镜素材、文字说明或文件可解码代替完整回看。先上传真实文件取得系统媒体 URL，不传本机文件路径。

视频和声音检查与剪辑导出共用实际素材解析：存在固定剪辑时，检查其固定文件和实际入点/时长，同一源镜头使用多份视频时每份都要看；不再用 Shot 最新采用或原叙事时长替代。声音按实际可听范围解析，包含项目库链接，静音、已删锚点或成片范围外的声音不要求听审。新选库声音同时保存实际 URL，浏览器全局库后来换文件不会悄悄替换本场；历史仅有浏览器库 ID 的音轨需重新选一次素材后听审。

服务能够核验检查项完整性、媒体字节、当前来源、依赖和已保存结论，不能证明评论诚实、责任人确实观看，或保证画面一定好。责任人在当前真实图声上作判断；代码测试和模拟媒体不是具体作品的创作验收。

## 变化、失败与旧成果

相关来源变化使旧检查变为 `stale`，旧内容、媒体、观察和候选保留；只有受影响的依赖需要重新检查，不清空全剧，不让人手动维护 hash 或技术版本。409要求重读当前内容并比较影响，不是盲目重试指令。无关编辑继续使用其仍有效成果。

分集创作方向纳入本集整场及后续检查，生成来源同时跟踪实际继承的分集画风；不因此让别集失效。整集总检记录其采用的各场已审视频内容；替换整场视频后，旧整集总检不能自动恢复为通过。重复检查同一视频或增补说明图不会强迫整集再审。

检查与返工上限沿用 `Project.productionWorkingAgreement` 和场次 `workRecords`。不自动重生成，不换任务、种子或会话清零次数。达到上限停止该项及其依赖，保留实际失败与已用次数交作者，继续不受影响的工作。约定零轮 Agent 审查时由作者完成真实检查，不给未看过的内容填通过，也不能以未审暂用记录绕过阶段依赖。

历史已生成成果和在途任务保留，不补发生成、不自动给旧成果盖通过。新的正式推进若缺检查则暂停在依赖处，读取已有成果完成必要检查后再继续。scratch仅供实验，不可直接采用为正式作品或借其跳过检查；转入正式流程仍须满足当前范围、来源和质量要求。

## 生成与交付边界

生成 preflight、submit、实际 dispatch 与外部媒体 import 都核验相应质量前置条件；沿用来源、容量、用户暂停和正式采用保护。预检成功、供应商成功、候选登记、技术检查和素材采用分别保留其含义，均不能替代下阶段的实际检查。

普通资产、故事板及摄影棚按钮传实际制作目标，项目请求不会因漏传目标自动变成 scratch；独立实验仍可明确选择 scratch。普通资产批次每目标提交一次，单次自动检查失败也保留候选，不隐式重画。页面等待超时先查询原执行；质量前置失败的等待任务进入 held，质量后来通过或修改无关策略都不自动重发，确认继续时显式重新加入队列。候选补充审计复用原候选 ID，并在服务器当前内容上增量保存。

独立配音与配乐同样执行前置检查。正式声音传 `purpose:"production"` 和 `{projectId,episodeId,sceneId,shotIds?}` 的target，通过当前范围preparation后可与画面并行制作；音色试听及独立实验明确 `purpose:"preview"` 且不带target，不冒称正式场次执行。Gemini TTS失败不隐式重发。三维世界建造/保存要求project_plan通过；场次白模静图登记和动态拍摄要求shot_plan通过，作为preparation的检查材料，不反过来要求尚待检查的preparation，避免循环依赖。

手工新增或拖动解除镜头绑定的配音使用场次级范围，整场准备通过即可生成；仍关联具体镜头时使用该镜头范围。场次旁白无需人为补绑镜头，也不新增审批。

`/api/assets/compose-video-segments` 和 `/api/assets/compose-episode-film` 生成的是待审合成预览；上传、下载或合成成功不等于正式交付。完整查看其实际视频，完成 `scene_cut` 和 `episode_cut` 后，通过 `Q/deliveries` 回取已总检的实际成片。该动作不重新编码成另一份未经观看的文件，不把之后再合成的新文件冒充本次已审成片。

作品交接记录当前通过/失败/待查阶段、实际检查与媒体位置、尚未精审内容、已用次数和下一步；项目历史交接保持历史，不当作新检查结论。
