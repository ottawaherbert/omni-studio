# 全局技能库流程梳理与收口（2026-09-29）

## 定位

Skill 是可重复使用的任务方法或补充要求，集中存放在全局技能库，各模块按当前任务选用。分类是整理标签，不是强制流程，也不限制使用模块。

保留两种已有执行语义：

| 类型 | 内容与使用位置 | 创建入口 |
| --- | --- | --- |
| 通用指令 | 普通规则文本，可在写作、制片提示词、互动、拉片等已有 AI 任务入口选用 | 统一「新建技能」 |
| 制作导演方法 | 结构化的表演、摄影、美术、声音等指导，由制作环节按职责读取；旧版文本继续用于分镜规划 | 同一个入口，选择类型 |

导演方法不是单独一套技能库。保留它的原因是已有制作流程依赖分工字段；若全部降成普通文本，会失去资产设计与分镜等任务之间的指令边界。导演类本身不应被无条件注入剧本或所有生成任务。

## 使用流程

1. **人工创建**：新建技能，默认通用指令；填写名称、分类（可留空）、规则。导演方法使用已有方法编辑器。
2. **AI 辅助**：在同一编辑器展开 AI 起草，说明需求；必要时查看或修改提示词。通用草稿先预览和编辑，采用到编辑区后再保存；导演方法沿用候选检查、采用、保存。生成不会直接写入技能库。
3. **管理**：名称/内容搜索，类型与分类下拉组合筛选，最近更新优先。详情可复制指令、编辑或删除。分类支持新增、改名、删除；删除分类只把技能移入未分类。
4. **使用**：回到对应模块选用。技能库不自动把技能绑定所有作品，不额外增加执行阶段。
5. **后续修改**：更新库里的规则用于后续选择。已生成任务或制作作品中的冻结快照保留，不自动重写旧成果。

复制回填继续受全局测试模式控制，导演编辑器的粘贴测试返回入口也遵循该开关。正常创作可以直接调用已配置模型。

## 本轮发现并修复

- 单独的「创建导演 Skill」和多个创建表单造成入口分裂；统一使用 `CreativeSkillComposer`，移除旧的重复人工/AI保存表单。
- AI 草稿在旧表单被标为人工来源；现在采用 AI 草稿后正确保存 AI 来源。
- 旧表单在没有预览对象时访问 `previewSkill.kind`，有页面报错风险；重复表单随统一流程移除。
- 横向分类条过长；改成响应式搜索、类型下拉、分类下拉和分类管理。
- 编辑器传入 `undefined` 无法通过 JSON 清除分类；现在使用明确空值，重载验证未分类。
- 旧导演文本被迫转换才能编辑保存；现在可保留旧规则修改名称或分类，转换结构仍为可选。
- 全局 store 在服务端保存/删除失败时伪造本地成功；取消该降级写入。读失败保留上一次服务端确认的内容并提示重试，失败不会标为已加载。
- Skill 文件标题中的引号/反斜杠往返不正确；新文件使用正确转义并兼容历史文件。
- 更新文件曾信任客户端 `_filename`；现在始终按 Skill ID 找到目标，避免更新错技能。
- 新建 ID 改为 UUID，显式重复 ID 被拒绝；空名称/空规则与分类重名得到明确错误。
- 推荐提示词不再假定所有任务都来自剧本模块。

未迁移或删除用户既有 Skill 文件、分类、作品资料和历史快照；没有重做 Skill 注入协议，也没有新增技能市场、自动绑定、权限层或工作流。
