# O.M.N.I. Studio 当前架构

更新：2026-11-09。handbookVersion：`2026-11-09.operator-v71`

本应用是本地影视与互动创作工作室。React/Vite 前端、Express API 和 SQLite 保持模块化单体。真实数据位于 `OMNI_Workspace`；自动化测试使用 `OMNI_DB_PATH` 指向临时数据库。

产品目标是帮助作者写好剧本、完成剧集和电影，以及制作有意义的互动视频游戏。功能只围绕这些创作结果补齐；保留现有 UI 设计、布局和风格，必要的功能改动沿用现有样式，不以架构整理为由重做界面。

生成工作台已接入项目资产、宫格预览和摄影棚，详细规格与验收边界见 [生成工作台设计](generation-workbench-design.md)。工作台清单与素材关系画布使用同一任务数据；画布外壳、工具栏和排版基础与互动模块共用，布局不改变剧情或分镜顺序。

### 角色身体与脸部参考分工（2026-11-09）

角色纯净参考统一为 `body_face`：左侧正/侧/背颈部至鞋底的身体服装图，省略头部与头发且无血腥效果，右侧为完整脸部大特写。分工是减少身体小脸与身份特写竞争，不承诺所有模型远景永不变脸或增加远景像素。旧版生成模板和版式选择已移除；旧图片、原提示词与候选保留为历史数据，不批量重做或冒充新版。

新图片与专用提示词保存在 `Character/AssetVariant.characterReferenceLayouts.body_face`；明确采用后才更新 `cleanReferenceImageUrl/cleanReferenceLayout`。`characterReferenceBoards` 仅提供新版稳定生成目标，旧通用角色板ID的纯净生成入口同样生成新版，旧专用提示词不再自动进入新生成。来源记录原始身份基准，避免采用自身输出就变成来源过期；身份、状态、原参考或风格变化使候选需重新核对。历史 `standard` 字段只用于保存旧素材，不能新建旧版任务。

身体/脸职责说明进入分镜与实际生成引用；故事画面保留完整人物头部，不复制参考板无头外观、四栏或白底。受伤/创可贴/换装等仍用状态变体，按镜头已接受的状态实际选择引用，明确需要的状态图片缺失则阻止；同组不同镜头可以保留各自基础/受伤状态。body_face参考仅可作角色身份，不能伪装为视频首帧。普通质量依赖、视频已审分镜要求与候选采用机制保留。

### 场景资产多视角（2026-11-09）

普通场景资产增加同一地点的主视图、反向平视、互补斜角全景与90度顶视布局，全部是二维空场参考，不依赖3D。主图沿用现有纯净参考；补充图存于 `Asset.locationViews`，昼夜、损毁等状态各自在 `AssetVariant.locationViews` 保存。视角不会创建新地点或覆盖主图，也不把画面朝向当剧情状态。

场景可在 `locationSpatialAnchor` 保存固定空间关系与各参考图的摄影机位置、朝向/拍摄目标；状态变体继承基础基准，可局部覆盖。方向采用作者约定，不从图片左右臆测东南西北。基准动态加入主图、补图、分镜与实际生成引用，保存过的用户提示词也读取最新基准；修改相关空间/机位使依赖视角需复核，不清除图片。主图与一个互补斜角覆盖足够即可继续，反打或调度确有需要再补其他角度；四个入口不代表四张必做。补充斜角不固定俯拍，机位和高度按明确设置。

反向与互补斜角使用同状态主图；顶视使用同状态前三张已采用图。生成工作台预检冻结真实输入，必需引用未发送、参考缺失/过期或模型容量不足则明确阻止，不静默删图。沿用候选、实际检查、采用和退回入口；保存了文件不等于空间一致性通过。主图、上游视角或相关设计变化只标记受影响视角需复核，保留旧图和候选，不自动重生成。

镜头通过 `locationReferenceViews` 选用所需场景视角，未填写沿用原参考规则。单镜、联合宫格和筹备检查读取同一选择及当前外观状态，不以基础场景图替代缺失的状态视角。顶视是布局参考，不能设为故事板或视频首帧；视频仍须使用已审分镜。旧项目无需批量生成四张图，制作中按镜头需要补齐。图片模型的几何一致性由实际看图判断，软件只保证引用、来源与保存流程可追踪。

### 分组制作与并发上传（2026-11-06）

场次内的制作单元通过 `PATCH /api/projects/:id/episodes/:epId/scenes/:sceneId/storyboard-units/:unitId` 单独保存。沿用现有 `manualStoryboard.boards`，记录有序镜头、画格动作、实际估时与起止状态，联合宫格各有自己的目标与媒体位置；整场总览保留其用途，不轮流覆盖成各个单元的参考。服务器读取当前内容、保留其他单元与历史媒体，不要求人工维护修订号；媒体采用和阶段检查仍走原入口。保存方案不会生成图、自动通过或追加审批。

ComfyUI 同一共享服务错峰准备参考素材，图准备好就放开上传通道，远端生成继续按配置并发。每个成功上传的文件随原任务保存，上传阶段有限恢复时不重传已成功文件；不同素材按内容摘要命名，避免同名覆盖。重启后每轮派发检查过期租约，仅恢复尚未 POST 的工作；POST 结果不明仍需对账、不自动重发。这些运行改进不保证模型正确遵守人物、道具或剧情，真实画面仍按制作约定检查。

生成上下文与资产界面共用按用途构建提示词的函数。没有保存专用提示词的纯净参考，直接按当前资产类型构建纯净布局，不回退到要求复合研究页的制作资料板；已写的提示词和当前身份、风格继续保留。多视图按资产需要选择；具体候选可用单角度消除重复物体歧义，不全局强制单图。

### 制作质量依赖与全局责任（2026-11-02）

当前制作按[质量检查与正式交付](production-quality-workflow.md)执行：总导演承担全局创作责任，制片统筹推进，各专业执行设计和实际检查，可由同一人或Agent兼任，不内置自治多Agent。固定8阶段为全剧总体、整场设计、拆镜、资产布景调度、整组画面、视频声音、整场合成、整集总检。先总体、再拆分、再总体；当前阶段未通过不得进入依赖下阶段，8阶段不等于8次请用户批准。

检查冻结当前实际内容及媒体，逐项明确通过/不通过和实际观察；来源变化只让相关旧检查失效，旧稿和媒体保留，技术版本由后台管理。保存草稿、失败候选和待审预览不等于放行。沿用制作约定与工作记录上限，不自动重生成；旧成果和在途任务不重发，缺检查时暂停新的正式推进，不自动补通过。普通制作保留，3D按需；选择3D或视频时须实际发送相应已核对构图/画面。scratch只供实验。合成导出是待审预览，正式成片由质量deliveries回取实际已总检文件，不重新编码；代码不能保证评论诚实或作品必然合格。

质检与导出共用实际固定剪辑及可听音轨解析，包括归档镜头、源入点、修剪时长和库声音。分集方向影响本集相关检查，生成来源记录实际继承的画风。整集总检关联各场当时已审的视频内容，场次成片替换后不会复活旧整集结论；同一文件重查不强迫重复总检。手工场次旁白可直接使用场级声音范围，不增设镜头绑定要求。

### 制片协作与非破坏剪辑改造已实现（2026-11-01）

[制片协作与交接改造方案](production-collaboration-design.md)已接通剧本、筹备、资产、可选3D、分镜、生成、声音、剪辑与审片的共同依据和交接。新增专业需求/事件状态、资产拍摄用途、实际观察、有限工作记录和只读结果索引；正常分镜默认单次生成，不自动评分重修。人和AI使用窄范围场次/镜头/协作/剪辑/资产/3D编辑工具，后台管理必要保存保护，无需手动维护技术版本。剪辑固定实际素材，切分修剪排序不复制叙事镜头，声音锚点及导出共用同一片段解析。旧作、候选、用户暂停和正式采用保护保留；隔离HTTP、浏览器、本地真实媒体与相关回归已验证，不等于具体作品创作验收。入口见手册。

### 场次人物与群演交接（2026-11-01）

副导演/群演协调明确承接导演要求，按事件落实在场人员、入退场、站位活动、人数规模与画内可见性；摄影看实际遮挡与规模，场记核对连续性，统筹汇合。静态试景也可摆人物代理，不依赖视频；空城模型与本场人物布置分开，合理无人场不填人。沿用现有场次 objects/frames、颜色及活动说明，无新增schema、审批或自动返工。运行时建城合同与剧本拆解提示同步此交接；场次演员检查器可编辑识别色。识别色不替代服装资产。完整规则见[背景人物与环境活动](virtual-studio-library-design.md#背景人物与环境活动)。

### 影视城 AI 建造（2026-10-26）

人工按钮与外部 Agent 共用持久建造任务：读取完整剧本/资产与现有世界 → 文本模型或外部返回声明式方案 → 真实几何/LOD候选与检查图 → 来源/CAS校验后应用。支持从零建造和跨集扩建，省略旧项不代表删除；模型可选，失败不静默改供应商或套样板。详见 [建造接口与人工流程](virtual-production.md)。旧聊天助手保持删除；这是影视城领域工具。

当前阶段优先确保 Codex 等外部 Agent 能凭说明书独立设计、提交、看图修订并保存，使用 `mode:"external"`，无需调用系统配置的文本模型。人工建城入口保留，系统调用外部 AI 服务的建城测试暂不推进；供应商故障不阻塞外部 Agent 使用本地建模和渲染工具。这不改变具体作品的图片/视频生成要求与暂停状态。

### 生成工作台（2026-10-22）

- 桌面默认展开专注工作区，主流程为“参考素材 → 检查并准备生成 → 生成结果 → 检查后采用”。清单与画布只是同一任务的两种视图；点击素材打开统一检查器查看来源、用途及是否发送，点击结果进入检查。高级参数、服务详情、批次与本机工具渐进展开，不默认同时堆叠。画布工具栏使用共享组件的独立工具行，避免遮挡素材。
- 人工覆盖与锁定由 UI 和 Agent 共用规则保护；允许作者显式恢复 AI 调整权。工作区按每个任务自身的目标读取来源和可用参考，不能用入口片段覆盖其他任务。输出尺寸继承实际工作流并按项目画幅对齐，不能用固定尺寸冒充各工作流默认值。
- “当前采用”以正式作品指针为准，曾采用但被替换的结果显示“历史采用”；明确恢复历史结果必须再次走正式采用接口。已采用页面的旧未选候选不计为新的待检查项，新产生的候选仍须检查。
- 服务部署、生成核心、参数预设及操作方式分开。能力目录从有效配置建立，合并同核心的参数版本并保留旧 ID；支持当前 Comfy API 工作流与已有 KIE 图像/视频适配。未接通的其他供应商能力不宣称可运行，旧配置不删除。
- 任务可勾选参考、指定用途和版本、上传素材，调整能力范围内的尺寸、采样、二采及 LoRA 参数。LoRA 开关与强度独立保存，关闭时编译为零贡献，指定加速核心保持锁定。AI 建议先显示差异，保留人工覆盖与锁定。
- 新接口 `/api/production/generation` 与 `/api/operator/generation` 共用 `src/server/generation/engine.ts`。草稿版本、固定计划、执行、暂停和画布布局分开持久保存。预检固定实际素材字节、种子、提示词和核心，执行只接受计划摘要；出队、上传前及 POST 前重新检查。
- 图片与视频暂停分别持久保存。具体作品的当前暂停和限定核心以已保存策略及最新用户指令为准，作品进度只记在交接，不在通用设计中固定某项目的旧暂停。人和外部 Agent 均可直接提交预检通过的固定计划，不要求另填图片/视频、服务、次数、预算或保存 grant。Agent 不能解除用户明确的暂停或冒充人工采用。旧生成 POST 入口要求固定计划，历史查询保留。
- 固定计划批次整体校验来源、版本和项目策略，不设额外授权额度。仅显式加入依赖等待队列后才自动重检，上游正式采用/真实帧提取与单纯生成完成分别判断。存在循环、来源变化或提交不确定时不盲目继续。
- 复用 Comfy 图片/视频共享队列，以实际服务 origin 或显式 `comfyQueue.executionPoolId` 归并额度，并用数据库短租约避免重复调度。当前服务额度来自配置，仍是 7 路共享，不按预设扩容。未知提交保留对账，Comfy 关联编号须验证实际工作流一致。无编号的未知提交在核对远端队列和相关历史后可显式释放本地占位，留下证据与操作身份，仍不自动重发或标成取消；后续关联在途编号重新占位。
- 结果按固定目标登记到既有资产、宫格、镜头或视频单元候选，保留历史版本；正式采用另行走版本与来源校验。本机裁切和真实视频末帧提取是独立处理任务，不冒充 AI 宫格或独立生成放大。H3 请求按帧对齐检查不超过 14 秒，不截短叙事来凑模型上限。 Comfy视频若内嵌API图与提交图存在已知差异，保留文件/候选并以technicalIssues阻止采用；无元数据不宣称执行已核实，元数据一致不代表实际内核或画面合格。
- 本轮开发验收使用隔离 SQLite 与模拟供应商；实际本机裁切、末帧提取及浏览器交互另有记录。未提交真实图片/视频生成，未完成真实宫格视频质量或独立新手用户试用验收，不能以代码检查替代。

## 外部制作与系统维护

制作 Agent 通过业务 API 操作作品，可在独立作品目录编写建模脚本和生成三维资源；不能修改系统源码、全局提示词、说明书或直接写数据库。已有命令启动、检查和必要时正常重启服务属于制作运行权限；服务可正常写业务数据与缓存。只有明确的系统开发/维护任务可改实现。操作入口、资产图用途与隔离启动统一维护在 [外部 Agent 手册](agent-guide.md)，不再复制另一套协议。已有作品、候选、原稿与保存合同不迁移、不清空。

## 可选高级工具：3D 虚拟制片

制片入口「3D 影视城」使用 Three.js。项目级影视城按全剧剧本建立，后续剧集沿用稳定地点和物体并扩建；场次方案只引用地点，保存演员、道具、事件状态和机位关键帧。普通流程继续独立使用，遵守共同质量阶段；不因未选择3D增加三维要求，不引入内部自主助手。

共享库与本剧布置分开：资产页「3D影视城」可安装完整“清水·河岸社区”、导入GLB、查看固定机位和巡视路线；项目可选择整城或部分地点加入并独立改装。完整社区包含道路、住宅、医院、学校、商铺、公园、河岸、外围街坊和地平线；客栈/实验楼旧样板明确只是建筑组件。机位PNG可通过固定版本的 `/library/studios/:id/previews` 后台拍摄和读取，供人和Agent实际看图。不能只看worldBrief或返回成功就宣布场地合格。

常驻Three.js场景、共享LOD、顶点色材质合批、空间分区实例化与增量远景合并共同控制负载；镜头路径预载并固定细节，后台拍摄可暂停续拍。系统提供真实结构取景能力和简化关节/持物代理，不宣称自动生成任意题材完整城市、精细表演、碰撞或最终画面。新剧接手先读共享库/当前剧本/影视城，按剧情补建；普通制作流程不受该高级工具约束。

建城质量以[专业片场筹备规范及能力审查](virtual-studio-library-design.md#可拍摄标准与筹备当前规则)为准：剧情动作、摄影、灯光、道具与群演共同决定布局，精建前试机位/动作。规范集中维护，不新增部门审批链；渲染v2统一人偶脚底基准，提供支撑面跟随、双段手脚、握点/肘向、座面高度与逐帧拿放。接触检查使用实际LOD网格、支撑射线与自适应动态采样，结果留存对象/镜头/时间及来源；当前范围的失败白模参考会阻止下游生成。检查不是刚体求解或导航；动态用途按制作约定粗看实际运动，静态用途不追加全片动态检查。旧媒体保留并按渲染版本标记来源变化，旧任务不得混帧续拍。

人或 Codex 等外部 Agent 自由选择构图图、白模宫格、运镜/动作预演或整场、整集、全剧白模 MP4。动态预演按正式镜头顺序及原时长拍摄，范围缺项明确报出；同镜头按关键帧插值，跨镜切换。白模是空间和拍法参考，最终人物/场景外观仍由独立资产提供，不能标记成已采用 AI 故事板。

世界、场次排演与视频任务独立持久化；UI 和 `/api/operator/previs` 共用版本与范围校验。白模参考默认不选，明确使用后跟踪相关布景/机位来源变更，提交与采用复核；不影响未使用白模的普通任务。完整白模视频不受14秒限制，交给生成模型的片段仍服从真实容量、用户指定 YZ H3 核心与原项目暂停。详细用法、JSON合同、API、渲染与能力边界见 [虚拟制片工具说明](virtual-production.md)。

## 剧本

写作首页是作品库，直接新建或打开作品。工作区保留故事资料、大纲、结构分场、正文及导出。侧边“写作任务”默认关闭，用户明确选范围与任务后才打开；可选 Skill、准备交付要求、复制给外部模型、粘贴返回并查看候选。单次文本 API 工具仍可用，不存在聊天驱动的自主规划、后台写作循环或全站助手。

领域位于 `packages/script/src`，API 与存储位于 `apps/api/src`，前端位于 `apps/web/src/features/script`。正文只存在于场景块中；导出由块派生。人和外部 Agent 共用 `/api/scripts` 项目保存与专项任务协议：读取当前稿 → 携带 expectedRevision 创建 job → 提交 result → 查看候选 → approve。单次回填不等于采用；冲突时保留输入，不覆盖新稿。故事/季/集/场作用域明确。精细段落与已有资料可直接在编辑器修改；尚无对应采用合同的分析只返回建议，不扩成整场重写。

大纲任务的读取和采用范围由服务端约束：`outline` / `story_outline` / `season_outline` / `unit_outline` 分别对应全剧、故事、季和单元。局部修改携带 `outlineRange:{start,end,text}` 与需要保留的 `outlineBeatIds`，任务保存原文区间、所有者和节拍身份；回填使用 `OUTLINE_RANGE_CONTRACT` 的 `content/nodes/beats`，不使用整份大纲替换格式。范围外文字、原节拍 ID、所属单元和场景关联保留，原稿改变后拒绝旧基线采用。完整大纲使用对应操作的 `{summary,outline}` 合同，季/故事已有原文必须进入任务上下文。

连续性与线索检查、时长估算位于“作品”菜单，属于独立领域工具。连续性工具可打开写作任务并明确勾选本次正文（每批最多 30 场）；`reviewSceneIds` 同时决定输入、允许引用的场景和检查记录，不把其他场摘要说成已读正文。跨集补分场以目标单元为锚点，包括空白单元；保留已有场次，只追加新场。

模板升级按默认指纹判断：已识别的默认随版本更新，作者自定义与不能判定来源的历史文本保留。显式“恢复默认”持久保存选择，后续刷新不会再被服务端旧模板覆盖；再次编辑自定义模板时解除该选择。长篇生产记忆检查故事阶段、结局与状态资料；集数不意味着商业变现需求，商业资料仅按作者要求提供，不要求非商业作品编造变现承诺。

旧助手的执行端点与程序已移除，历史数据库不清空。作品库“历史内容存档”及 `/api/script-archives` 提供分页只读导出；旧助手 job 只读，不能复活执行。新写作任务保留输入、候选、返回尝试和采用记录。外部 Agent 不依赖旧聊天记忆，先读当前作品和作用域，再使用正式保存或任务协议。

## 制片与互动

制片继续负责剧本来源、资产、场次、分镜、配音和摄影棚；互动负责图、节点、状态、绑定与播放。通过 `packages/domain/src/scriptDelivery.ts` 接收独立剧本快照，不导入剧本内部领域对象。制片改稿保存在制片版本中，源剧本由剧本工作区编辑。媒体、既有制片快照和互动绑定数据不随本次源码清理删除。

剧本与制片各自独立运行：制片可直接接收外部文本，项目列表不等待剧本服务；已导入副本只在作者检查差异并采用后更新，历史 `safe_auto` 也按手动采用处理。交付保留画幅、作者要求、人物简介和已确认资料的适用范围。互动按需调用两者，绑定固定交付版本，不回写源剧本；查看绑定稿与编辑作者当前稿明确分开。

同一作者稿的线性制片与互动制片目标分别显示、保存和回收；普通导入只复用线性目标，不能按作者稿ID把互动项目合并进去。源剧本同步采用核对已查看的来源与制片版本，当前未完成的本地编辑先保存或取消，异步同步期间不重置其草稿。互动媒体更新后保留旧试玩快照，显式按当前内容重新构建。

交通工具沿用正式资产体系，以 `vehicles` / `vehicle_board` 提供场次绑定、状态变体和图像引用；不同变体或参考图不复用同一视觉包。筹备页的精简读取不代表作者删除文字板，修改交通工具前载入完整场次并完成保存；旧正式确认记录缺交通工具板时要求重验，不伪造已确认状态。

制片分集以 `productionRevision` 校验保存，旧页面写入返回 409，并在本机保留草稿。删除分集走显式删除接口，整项目快照缺少某项不代表删除。保存失败不会后台重放旧稿；导出先完成保存。互动图谱离页前保存，失败留页并保留本机恢复副本；剧本返回交接前完成当前稿保存。剧本映射更新不清空互动已确认媒体。

### 创作提示词工作区（2026-10-19）

分镜、项目资产与摄影棚的高频提示词入口使用非模态工作区。桌面为右侧面板，窄屏为底部面板；主画布按剩余空间重排。关闭保留当前页面会话内最近 40 个任务草稿，按项目、分集、场次和任务隔离；刷新页面不承诺恢复。执行中同一任务禁止重复提交，失败保留输入，成功结束提示词编辑；候选采用和正式版本保护继续由原业务流程负责。普通模式的外部视频入口提供提示词复制，结果通过摄影棚“导入视频”加入；测试模式保留原有手动回填能力。

来源变化和缺少材料使用共享提醒，不阻断继续编辑。动作真正需要的输入、版本冲突、媒体采用与保存检查仍然有效。视频连续性使用本场有序相邻镜头的动作、调度和光影文字证据，进入单元提示词及摄影棚请求；未知、缺失或非连续范围不推测衔接，也不自动新增媒体参考。互动等待点沿用首尾闭合与运行时超时约束，不固定视频后 60% 为循环。提示词与请求通过测试不代表生成媒体已经通过视觉验收。

### 普通制作的审查分工

普通制作默认Agent负责筹备、执行和有限粗审，作者负责精审。开工一次询问候选数（不固定两次）、粗审轮数/范围、明显大问题返工次数或时间上限、制作暂用与交付方式；有答复直接沿用，新会话读取Project.productionWorkingAgreement。存取和问法集中在[主手册](agent-guide.md#首次一次问清后续按约定推进)。不新增逐镜审批、grant或自动重试状态机，不把这些偏好混入画面提示词/来源指纹使已有素材失效。

粗审只修影响使用的明显大问题；细节与审美交作者，达到约定上限保留问题候选、继续无关制作。下面的专业质量维度供设计及人工精审使用；固定阶段检查项须逐项记录实际观察，不要求反复循环打勾。最终验收不能由技术成功或Agent制作暂用冒充。来源、幂等、实际容量、数据保存与用户暂停保护保留；严格批量QA只适用于作者明确选择的批量管线；普通API制作同样遵守当前质量阶段及其依赖检查。

### 场内视觉统一与切镜流程

此规则同时面向系统内模型与接手项目的外部 Agent。入口见根目录 `AGENTS.md`，当前作品状态见 `doc/handoff.md` 顶部。以整场戏为设计与验收单位，但不强制每个镜头连续动作。正反打、反应镜头、插入镜头、蒙太奇、时间省略和有意越轴均可使用；判断标准是观众能理解空间、事件顺序与叙事重点。

1. **核对事实与资产**：读本场完整剧本、已采用资产和当前制作版本。区分固定环境与剧情逐步变化的状态；邻场只能供理解，不把邻场人物、地标或后段事件搬进本场。角色、场景和独立道具分别提供资产参考图，不混成一张多资产图。
2. **先设计整场，再写单镜**：明确关键地标、人物关系、光源、事件顺序及信息揭示时刻。沿用现有 Shot 字段：`motivation` 写本镜新增信息，`editingNote` 写切镜理由与承接方式，`blocking` 写空间关系，`continuityNote` 写相关入镜/出镜状态，`visualAction` 写可见动作。不适用的项可说明；未知事实不猜。必要时重拆镜头，不锁死旧镜头数，不为模型时长上限牺牲剧情。
3. **整组画面预览**：需联合设计时，用整场方案和独立资产参考让图像模型一次生成整组宫格；长场可分组，但保持相同空间依据并检查组间边界。按叙事顺序核对人物、场景、画风、光影、道具状态、切镜动机与揭示时机。旧单镜图的确定性拼接是检查图，不等于 AI 联合生成，也不能据此宣称一致性已修复。
4. **视频生成**：使用通过检查的宫格与相关独立资产，明确格子顺序、各段动作和机位变化；不能让模型把宫格边框当成视频内容。按所选模型实际参考图容量与时长能力拆生成单元，保持完整叙事镜头与生成片段的区别。超过单次上限时拆单元，不能直接压缩整场。
5. **粗剪与人工精审**：Agent按约定轮数粗看明显剧情缺失、人物错认、空间/道具严重矛盾、噪点黑屏或明显穿模，必要时在约定范围内修受影响材料。尽早交整场粗剪与简短问题；作者负责细看切点、声音和表演。没有新变更不重复检查，不默认逐帧抽查每条视频；保留旧候选与记录，制作暂用不表示作者验收通过。

**估时和剪辑依据**：`Shot.duration` 是可修订的叙事预计秒数，允许正数小数，不受模型最低生成时长限制。`visualAction/dialogueLines` 写内容，`motivation` 写本镜新增信息或情绪作用，`editingNote` 写动作/对白/反应的估时依据与切出条件；动作和对白可能重叠，不机械相加。默认值、字段齐全和预算加总都不是节奏验收。先按内容估时，再按供应商档位/余量确定请求时长，实际输出时长另测，时间线用源入点和保留长度剪接。必要的长镜头、停顿和有意等长均允许；不得靠慢推、重复动作或无信息停留填满单元或目标片长，也不得为凑长度机械补剧情。

现有生成context、workspace每个目标的sources和固定plan返回只读`timingReview`：逐镜内容/时长/目的/切出依据、缺项及整场等长/统一慢运镜提醒。`basisStatus:described`只表示文字已提供，`creativeStatus:not_assessed`不能改成自授通过；这是检查线索，不是语义/视觉评审。疑点不增加审批或禁止生成，实际容量、无效时间与来源冲突仍拦截。正式修订镜头后刷新草稿并重新预检，旧计划不能继续提交；不删除旧素材，先看能否正常速度剪用。粗审/制作选用记录沿用原review与时间线，精审交作者；非阻塞提醒不要求反复补表或耗尽所有疑点。

**时长先于宫格布局**：在生成视频参考宫格前，先估算各镜动作、完整对白与停顿所需时间，按合理叙事切点分成模型可执行的单元，再决定每单元的有效格数和布局。格子表示关键画面，不等于等长视频段，也不一定一格一镜；需要动作起止图时须标明属于同一镜头，不能重复计算该镜时长。不固定九格，不为填满布局添加镜头，也不按总览图行数机械分组。整场总览可另行生成，但展示时明确其总时长、镜头归属与分组；视频请求仅使用对应单元画格，不能让模型猜测如何从超时总览中取舍剧情。当前指定 H3 工作流每次最多 14 秒，不能因用户提出 15 秒绝对上限而提高现有工作流限制。时长合规仍需核对动作密度；执行不稳时进一步拆成较少镜头，以共同资产、必要的相邻画面参考及明确的边界状态维持统一，再剪辑成场。请求时长与实际输出时长分别检查，后者未实测不能宣称达标。
联合导演板 `director_board` 的页面保留同一镜头的多个有序关键状态，镜头范围和叙事时长只按唯一 Shot 计算；`shot_grid` 仍每镜一个代表格，两种模式不可混用覆盖校验。

当前代码把共同规则注入默认与旧自定义分镜任务、分镜质检/修订及整组故事板图像提示词；图片提示词也接收连续性和剪辑依据；视频接收本场有序相邻镜头的剪辑依据。故事板来源摘要包含这些依据，修改后旧图需要复核。上述是提示词与来源追踪能力，**不是自动视觉理解已经可靠验收的保证**；接手 Agent 仍须检查实际媒体。

页面入口为 **制片 → 分镜与故事板**。分镜默认按叙事顺序展示图片、时长与动作，点击镜头才展开编辑；依据和视频生成分组按需展开。故事板展示联合图与逐格映射，整场总览与视频片段分开查看。顶部“生成故事板”直接打开共用生成工作台，不要求先建立视频单元；摄影棚负责选片、声音与剪辑。清单与无限画布共同组织参考、参数、任务和结果，画布位置不改变镜头顺序。以下领域能力保留：

- **本场设计**：`Scene.visualPlan` 保存固定空间、光线、整场起止状态，以及连续事件、时间跳跃、平行事件、闪回或独立场次的关系。作者明确选择来源场次，分别填写继承、改变与转场依据。来源场次按需读取完整视图，不把列表摘要误作“没有状态”。
- **镜头与时长**：按实际工作流的容量与多镜头能力检查分组；叙事短镜低于最低请求时长仍可保留，生成余量用于剪辑，不要求延长表演。分组建议只作容量草案，作者结合切镜理由调整边界。应用时通过现有单元拆合逻辑保存，镜头时长不变，完整旧单元和媒体进入 `manualStoryboard.unitHistory`，镜头顺序匹配时可恢复。静态分镜按镜头时长试播，用于朗读对白和检查节奏；不模拟动作、不自动配音，不等于生成视频。
- **宫格预览中的总览与共同参考**：上传等分画格的联合总览，明确原图和单格像素、行列与镜头映射。总览可超过单次视频时长，裁切只提取各单元对应画格，作为 `overview-extraction` 待审候选，不自动采用、不冒充新生成高清图。一镜多格可在任务排版中映射；裁切到视频片段时，显式选择对应关键画格，不自动取第一格或重复计时。长场优先共享原始资产与本场空间基准，必要时增加绑定具体镜头的衔接参考；画格代表图不声称是真实视频尾帧。空间与衔接参考进入图像生成输入并计入模型容量，超额要调整，不静默丢弃。
- **宫格预览中的衔接检查**：并列检查组间代表画面及跨场交接，记录观察和未解决问题。检查记录绑定当前计划、镜头、参考、候选和来源终态；变更后重新检查。它只表示作者检查过计划，既不是“问题全部解决”，也不替代视觉 QA 或成片验收。

宫格预览默认以实际候选画面为主，可切换整场与单片段，点击画格后只显示当前镜头的代表图、动作、状态、切镜依据及所属整页候选。相邻对照优先使用当前宫格中的画格；独立镜头图与整场总览仍可回退查看。整页采用明确显示影响格数，经作者检查后走原正式采用与来源校验；拒绝、过期及来源已变化的候选供对照。采用只影响本页，不能由单格点击暗示整场通过。窄屏用范围下拉选择与可展开的底部详情，点击画格时定位该片段详情。

导演、画风、画幅和新片段参考模式放在本场设置；单元详细制作、提示词、其他媒体候选和历史记录按需展开。准备宫格时缺少图片提示词，先打开原提示词准备流程；视频资料缺少时同样引导整理，仍由原候选审核与生成入口执行。镜头编辑每次只显示所选镜头，未保存草稿按项目/分集/场次/镜头在浏览器会话中保留，正式保存仍校验原稿与最新版本。顶部不再把“镜头与提示词齐全”称为“当前场准备已完成”；已保存、候选待检查、参考已采用、来源变化、视频与成片验收保持不同含义。进入摄影棚时保留所选片段及对应镜头范围。

场景基准进入分镜规划、故事板图像、单元视频提示词和摄影棚请求。单元提示词始终接收完整场次的相邻镜头，不再将局部数组误当整场首尾；指定边界参考的文字与图片仅作用于对应镜头范围。改编组后，不允许把原整场大图继续标成小单元的已采用参考；旧图保留为历史，需按范围裁切并复核。面板草稿在当前浏览器会话中保留，正式保存走原项目存储、版本校验与保存队列。

项目暂停生成的要求由交接记录持久保存。图像预览与视频生成分别记录任务、暂停和验收状态。新会话按用户制作指令推进，不以缺少 grant 为阻塞；单纯读取项目不会自动提交任务。

## 冗余收敛后的责任边界（2026-10-22）

项目级制片阶段仅用顶部导航切换，不在页面下方重复放置整套阶段卡片、流程展开区或上一阶段/下一阶段导航。场内使用“分镜 / 故事板”内容视图，生成分组和依据按需展开；说明集中在指南，页面保留当前内容和来源状态提示。保存依据不因当前正在查看镜头而隐式重建生成分组；只有边界或目标模型变化才应用分组，仍走原版本校验及历史归档。

图片/视频的新提交由 GenerationWorkbench 与服务端 generation 引擎共同负责；独立实验任务使用 scratch 作用域，全局任务不创建生产项目。UI、旧按钮桥接与 worker 使用相同计划、暂停和执行合同，历史任务查询仍保留。音频继续使用专用配音/BGM 合同。

项目资产只有 ProductionAssetProfile 一个正式详情；GlobalLobby 的项目索引跳转到该详情。概念图、多视图、全景是原始资料，不等同于制作板或纯净参考；采用仍由对应领域校验。全局资产是复用模板，不能直接编辑项目实例。全局音色保存可复制的 VoiceSettings，角色选择后拥有独立副本；旧任意接口模板是兼容档案，不能宣传为已接入角色配音。

摄影棚只负责制作对象、选片、导入、声音和剪辑；内部参考/参数/提交在生成工作台，外部制作草稿在折叠区。新方案沿用当前描述、参考与参数，作者可继续修改，不能新建时静默清空。worker 使用稳定 scratch 目标，预检通过后直接提交，不需要范围 ID 或生成授权环境变量。同一次提交恢复旧记录，未知结果不自动重试。视频是否含原声以实际音轨检测记录。

已完成的代码与隔离验收、真实服务和创作验收边界以 handoff 最新检查点为准。Veo 参数依据官方接口说明 https://ai.google.dev/gemini-api/docs/veo ，真实组合仍需服务验收。


## 分镜、故事板与外部 Agent 的共同操作合同（2026-10-23）

本次自动化使用者是 Codex 等外部 Agent。系统提供正式读写与媒体能力，不增加一个要求用户先填写导演表单的内部 Agent 流程，也不把连续性变成逐镜强制动作衔接。联合图和参考帧帮助创作，仍需看实际画面和剪辑判断质量。

- 叙事镜头拥有动作、时长、对白、状态与切镜意图；故事板画格通过镜头 ID 映射到这些内容，可以一镜多格；视频任务按供应商容量选择对应范围。三者不再必须一一对应。`GenerationTarget.kind=scene` 用于整场或明确镜头范围的联合故事板，不接受整场直接生成视频。`storyboardLayout` 保存行列与逐格镜头 ID，空格可留在末尾；预检把映射写入固定计划，采用使用结果原计划的映射而非后来修改的草稿。
- 故事板候选留在生成执行记录，正式采用后写入 `Scene.visualPlan.overview`，原总览进入 `overviewHistory`；不把整张图塞进首个镜头，不清空原单镜图、视频或单元。来源指纹变化后提示复核。已有 `board`/`video_unit` 目标与历史候选继续有效。
- 参考的来源与用途分离。`sourceShotIds`、`sourceTakeId`、`derivedFrom` 记录从哪里来；`role` 指定这次参考人物、空间、构图、动作、首帧或尾帧。同场其他镜头的视频和图片可显式选择，不自动要求下一镜沿用原机位。整场宫格不能作为超出当前范围的视频序列。共同空间图和只作用于指定镜头前的边界图都进入实际引用列表并计入容量。
- `extract_frame` 支持 `framePosition=end` 与 `framePosition=time` / `frameTimeSeconds`。后者按原视频真实时长校验；前者解码末段保留最后一帧。输出默认是未勾选的构图参考，记录原媒体版本和时间，作者/Agent 再选择用途。不能把外部图片导入伪装成系统实测取帧。
- 能力、图片/音频/视频容量及可调参数来自现役 catalog；核心工作流不因选择参考而改变。当前用户指定 YZ H3 核心、14 秒限制和服务共享并行队列继续沿用。整场 25 秒的故事板不会因此变成一次 25 秒视频请求。

具体请求顺序、字段、外部导入、恢复和采用边界统一见 [操作手册第5节](agent-guide.md#5-生成与外部媒体回填)，不在本文件维护另一套步骤。多格总览裁切到视频单元须明确镜头和状态，裁切仅重新排版、不增加原生清晰度。实际视频与成片需观看、听声并记录证据。

测试环境必须在加载任何可能间接依赖数据库的模块之前设置临时数据库路径，并断言 `db.name`。静态导入供应商 catalog 可能提前载入数据库，不能在其后才设置环境变量。测试数据和作品数据不得混用。


## YZ H3 核心与多模态参考（2026-10-24）

用户指定的是「YZ金鱼-MiniMax H3 终极篇-文武双全」工作流的生成核心：模型、加速 LoRA、SelfLift 双采和 LMS 放大。作者示例的三图/四图槽位不构成模型能力上限。已有 API 图及参数预设位于 `src/config/comfyPresets.ts` 和当前服务配置；不能凭记忆用其他模型或简化采样器替代。标准、动作等不同核心仍分开；同核心的步数/尺寸变化是预设，不再因参考槽位数量另造方案。

- `src/server/generation/h3References.ts` 只对能识别的 H3 原生 reference conditioning 扩展输入。保留源图的模型、LoRA、采样、解码及放大节点；遇到未知参考依赖或自定义音视频链路时不自动覆盖。首帧/文生视频工作流不强行改成多参考。生成时只编译勾选素材对应的分支，未用加载器和连接删除。
- 新任务读取 `/api/operator/generation/capabilities` 返回的现役方案；`referenceAdapter=h3_multimodal_v1` 是多素材适配，`supersededBy` 指向替代方案。旧任务及固定计划仍使用原配方和历史 ID，不能静默改写；原三图/四图例子从新任务默认选择中收起。用户在同一生成工作台选择素材、用途、预设和高级参数，清单与画布共享数据。
- 本版按原生节点协议暴露最多 9 张图片、3 段视频、3 段独立音频，任意组合至少一份，不要求填满或每类都有；这不是对所有模型和线上 API 的全局限制。实际服务未证明支持的组合标为实验，不伪称服务实测通过。接入其他服务时仍以该适配器实际能力为准。
- 素材按用途选择：人物、空间、道具、构图、单元宫格、动作视频、人物音色或完整对白。视频参考当前只接画面帧，不隐式引用视频原声；需声音时单独添加音频。视频按 24fps 读取，至少 5 帧且不能长于本次生成时长，独立音频片段当前至多 15 秒；预检测量并拒绝超出范围的文件，不静默裁剪。输出仍执行既有帧对齐及 14 秒上限，不能把参考音频的时长当成输出许可。
- 角色声音仍由「项目资产 → 角色资料 → 角色声音」拥有。`voiceSettings` 保存配音配置，`voiceReferences` 保存可试听的音色样本和历史。生成上下文提供本次角色的样本，默认不发送；`sourceCharacterId` 标明归属，`usageNote` 可写具体对象与使用要求。更换默认声音或样本触发来源复核，不改已有视频。未来 ComfyUI 音频生成接入应继续使用这一归属与媒体引用，不另建一份人物音色档案。本轮没有接通 IndexTTS。
- `voice_timbre` 只要求声音身份，台词来自本镜剧本；`full_dialogue` 参考完整对白和表演节奏，不保证逐字复现、口型准确或原音频波形复用。需要原对白逐字确定时，仍须使用已验证的声音制作/剪辑方式并实听验收。编译提示词按实际发送顺序生成 `<Picture N>`、`<Video N>`、`<Audio N>`，各类从 1 开始；不得手写与实际槽位错位的编号。
- 外部 Agent 的操作顺序：读取 handbook/上下文/现役能力 → 选定用户允许的核心与参考用途 → 调整参数 → 预检查看固定计划及素材编号 → 未暂停且预检通过后直接执行 → 查看与听审候选 → 记录结果及采用状态。Operator review 接受实际观察说明、候选 contentHash、固定计划 sourceHash 与当前制作版本，经来源/技术/CAS 校验后正式采用；服务端记录 external_agent，资产采用审计同样保持外部身份。不能冒充 creator 或直接改指针；项目策略中仅 allowExperimental 可由已获用户授权的外部 Agent 带说明和 CAS 确认，并记录外部审计，其余策略由作者维护。沿用用户指定核心，Operator 不得自行解除暂停或修改指定核心。输入能编译、任务成功和创作效果通过是不同结论。

协议依据：[ComfyUI H3 原生教程](https://github.com/Comfy-Org/docs/blob/main/tutorials/video/minimax/minimax-h3-native.mdx)、[ReferenceToVideo 节点](https://github.com/Comfy-Org/docs/blob/main/built-in-nodes/MiniMaxH3ReferenceToVideo.mdx)、[VHS 视频加载节点](https://github.com/Kosinkadink/ComfyUI-VideoHelperSuite/blob/main/videohelpersuite/load_video_nodes.py)。协议声明不替代当前部署验证；实际进度与服务限制记录于 handoff。

## 生成操作简化（2026-10-25）

用户已经要求制作时，不再要求用户另行声明图片、视频、服务、次数、预算、有效期或执行授权命令。预检固定的是实际输入和参数，不是审批表。页面移除费用确认勾选及范围委托设置；单次、批量、依赖等待和 worker 都能在没有 grant 的情况下执行。任务成功仍不等于创作验收合格。

旧 grant 数据和携带 grantId 的历史执行仅作兼容：明确携带旧 grantId 的请求仍按旧记录检查，防止已撤销的旧队列意外恢复。新任务不创建、不要求 grant；历史文档或交接中的“grants=0 必须阻塞”已经失效，不得据此再次要求用户授权。用户明确暂停、指定工作流、人工锁定、来源版本、防重复提交、实际服务并发和未知结果对账仍生效。

### 完整三维世界标准（2026-10-26 纠偏）

外部 Agent 在搭建或改造世界前必须阅读[影视城设计顶部纠偏](virtual-studio-library-design.md#本轮纠偏完整世界不是若干建筑的陈列)。建筑组件、街区和整片世界分别管理；当前客栈/实验楼组件不是影视城验收答案。按整剧与时代规划地形、道路与步行网络、地块/街坊、功能配套、公共空间、周边和远景；不能把少量房屋或随机复制建筑当成完整社区。

项目世界可保存 `worldBrief`（范围、地理、交通、配套、远景、缺口），地点保存 `spaceId`、`usage`、`detailTier`。同一明确物理空间的周边自动参与取景和来源校验；旧无 `spaceId` 地点保留本地拍摄语义，不擅自推断相邻。三维文件保留原件，运行模型为无贴图、非金属的参考版本；远处降低细节，不能直接删空环境。

当前新增库/模型/后台拍摄接口见实时 Operator `virtualProduction`。功能接通不等于完整世界已经建成；须检查鸟瞰、沿街正反向、转角、出入室内、窗外、高机位与剧情路线。实测性能和生成成功也不替代世界画面验收。新会话应读取已建区域和未完成项，扩建既有世界，再安排场次，不能逐镜搭孤立背景。
