# O.M.N.I. Studio 当前架构

更新：2026-10-19。handbookVersion：`2026-09-20.operator-v48`

本应用是本地影视与互动创作工作室。React/Vite 前端、Express API 和 SQLite 保持模块化单体。真实数据位于 `OMNI_Workspace`；自动化测试使用 `OMNI_DB_PATH` 指向临时数据库。

产品目标是帮助作者写好剧本、完成剧集和电影，以及制作有意义的互动视频游戏。功能只围绕这些创作结果补齐；保留现有 UI 设计、布局和风格，必要的功能改动沿用现有样式，不以架构整理为由重做界面。

## 剧本

前端沿用作者认可的模式下拉框、Skill 选择、聊天和可点击想法；当前实现以历史提交 `f59cef58` 的这些交互为恢复依据。修复内部逻辑、存储或架构不等于授权重做界面。作者输入是聊天消息，不需要先分类为想法、大纲或正文。

新领域位于 `packages/script/src`，API 与存储位于 `apps/api/src`，前端位于 `apps/web/src/features/script`。正文只存在于场景块中；导出文本由块派生。项目配置、故事时间、展示顺序与制作时间分开。时长目标、估算和实测互不覆盖。模型输出须经版本检查和人工采用。

## 制片与互动

制片继续负责剧本来源、资产、场次、分镜、配音和摄影棚；互动负责图、节点、状态、绑定与播放。通过 `packages/domain/src/scriptDelivery.ts` 接收独立剧本快照，不导入剧本内部领域对象。制片改稿保存在制片版本中，源剧本由剧本工作区编辑。媒体、既有制片快照和互动绑定数据不随本次源码清理删除。

剧本与制片各自独立运行：制片可直接接收外部文本，项目列表不等待剧本服务；已导入副本只在作者检查差异并采用后更新，历史 `safe_auto` 也按手动采用处理。交付保留画幅、作者要求、人物简介和已确认资料的适用范围。互动按需调用两者，绑定固定交付版本，不回写源剧本；查看绑定稿与编辑作者当前稿明确分开。

交通工具沿用正式资产体系，以 `vehicles` / `vehicle_board` 提供场次绑定、状态变体和图像引用；不同变体或参考图不复用同一视觉包。筹备页的精简读取不代表作者删除文字板，修改交通工具前载入完整场次并完成保存；旧正式确认记录缺交通工具板时要求重验，不伪造已确认状态。

制片分集以 `productionRevision` 校验保存，旧页面写入返回 409，并在本机保留草稿。删除分集走显式删除接口，整项目快照缺少某项不代表删除。保存失败不会后台重放旧稿；导出先完成保存。互动图谱离页前保存，失败留页并保留本机恢复副本；剧本返回交接前完成当前稿保存。剧本映射更新不清空互动已确认媒体。

### 创作提示词工作区（2026-10-19）

分镜、项目资产与摄影棚的高频提示词入口使用非模态工作区。桌面为右侧面板，窄屏为底部面板；主画布按剩余空间重排。关闭保留当前页面会话内最近 40 个任务草稿，按项目、分集、场次和任务隔离；刷新页面不承诺恢复。执行中同一任务禁止重复提交，失败保留输入，成功结束提示词编辑；候选采用和正式版本保护继续由原业务流程负责。普通模式的外部视频入口提供提示词复制，结果通过摄影棚“导入视频”加入；测试模式保留原有手动回填能力。

来源变化和缺少材料使用共享提醒，不阻断继续编辑。动作真正需要的输入、版本冲突、媒体采用与保存检查仍然有效。视频连续性使用本场有序相邻镜头的动作、调度和光影文字证据，进入单元提示词及摄影棚请求；未知、缺失或非连续范围不推测衔接，也不自动新增媒体参考。互动等待点沿用首尾闭合与运行时超时约束，不固定视频后 60% 为循环。提示词与请求通过测试不代表生成媒体已经通过视觉验收。

## 共享能力

供应商密钥只在服务端使用。通用文本传输与旧剧本 Agent 已分离。Skill 原始内容、导演方法、画风、媒体与任务基础设施继续由各模块维护。

Skill 可选标注用途、适用任务、作品形态和说明。元数据用于筛选和选用提示，不自动添加、删除或采用 Skill；旧文件无需迁移，既有任务保存版本快照。用途不替代通用指令、导演方法等原有类型。

## 自动化

先读取 `/api/operator/capabilities`、`/api/operator/workflows` 和 `/api/operator/handbook`。使用稳定项目 ID、正式业务 API 和运行记录；遵守 draft → QA → commit 的制片合同。实际端点与输入以实时 capability 为准。人工编辑、模型候选与采用是不同动作，不得伪造审核通过。

## 验证与文档

`npm run lint` 检查类型，`npm run build` 构建应用，`npm run test:script` 检查新剧本领域与持久化。测试、Mock、真实媒体测量和作者创作验收分别报告。README 负责启动；本文件负责应用边界；handoff 只记录当前状态。旧设计不保存在工作树中。

`npm run test:module-readiness` 覆盖三个模块的内容隔离、交付、并发保存、绑定和导出前保存，使用临时数据库与本机测试服务，不调用真实模型。
