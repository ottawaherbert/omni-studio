# 电影的幕、叙事段落与分场：资料调研及流程补充

日期：2026-09-29  
性质：对多种作品形式流程报告的补充与修正，仅调研和方案，未修改业务代码。

## 一、结论

**电影当然可以分幕、分叙事段落。前一份报告将电影概括成“大纲 → 分场”，没有说明中间的结构组织，表述不完整；当前产品也确实缺少可明确操作的幕／段落层级。**

但有三个不同问题：

1. 故事如何组织：全片、幕、叙事段落、场景，以及贯穿其中的人物和情节线。
2. 作者如何开发：构想、概要、结构大纲、分场、正文，过程中允许交替修改。
3. 最终剧本文档如何排版：场景标题、动作、角色名、对白等；不一定把“第一幕／第二幕”写在正文里。

没有显式幕标题，不等于没有幕结构；支持结构规划，也不等于每部作品都必须按同一幕数完成一套表格。

对当前系统的建议是：保留四个主页面，在“故事大纲”中提供幕与叙事段落的规划，在“分场规划”中让场景与这些段落关联。长片由 AI 先提出可调整的结构，再分段、逐场展开，作者主要审阅与修改。

## 二、电影常见的结构层级

| 层级 | 它解决的问题 | 与相邻层级的关系 |
| --- | --- | --- |
| 全片 | 整个故事追随谁、发生什么、最终落到哪里 | 包含完整叙事发展 |
| 幕 Act | 故事进入了哪个大的发展阶段，核心局势如何改变 | 通常包含若干叙事段落 |
| 叙事段落／序列 Sequence | 一段相对集中的行动、目标、问题或体验如何展开并产生结果 | 可以跨多个地点和场景；不是固定数量的戏 |
| 场景 Scene | 谁在什么地点和时间做了什么，发生了什么变化 | 是正文展开的主要单位 |
| 节拍 Beat | 某个事件、认知或情绪如何发生变化 | 术语粒度并不统一，不适合强制等同一场戏 |

这里的“段落”指叙事段落，不是文字换行的自然段；“序列”也不直接等同于分镜镜头序列。

Final Draft 的官方大纲说明给出了 Act → Sequence → Scene 的层级组织示例。它证明这些层级可以共同存在于一份大纲中，无需每一层独立成为一个主页面。[Final Draft：How to Outline a Screenplay](https://www.finaldraft.com/learn/going-from-outline-to-script/)

### 三幕与八序列怎样看

三幕是常见的电影分析和规划方法：建立故事与主要处境、发展行动与阻力、走向结果。美国电影艺术与科学学院的教学资料介绍了这一模型，同时提到作者可从场景卡、大纲或故事处理稿入手。[Academy：Screenwriting Activities Guide](https://www.oscars.org/sites/oscars/files/complete_screen_writing_activities_guide.pdf)

八序列法是更具体的一种拆解方法。Final Draft 的教程给出“第一幕两段、第二幕四段、第三幕两段”的示例；应将它理解为帮助组织故事的方法，而非对所有电影的统一要求。[Final Draft：8 Sequence Structure](https://www.finaldraft.com/blog/8-sequence-structure-the-best-kept-screenwriting-secret)

系统可以建议三幕或八序列，但不能仅因为作品是电影，就强制特定分钟发生转折、每幕固定场数、每场必须反转。作者也可以采用章节式、多视角、非线性或其他安排。

## 三、好莱坞、Netflix、HBO 的公开资料说明了什么

这些不是三套互斥的编剧格式。好莱坞是广泛的产业语境；Netflix 和 HBO 的具体项目，由不同创作者以不同方法开发。本次证据包括专业教学、创作者原始访谈和剧本样本，**没有查到可据以宣称两家公司所有项目必须遵守同一幕数的公开统一要求**。具体委托与交付合同可能另有规定。

### 3.1 Netflix 电影案例：《玻璃洋葱》

Rian Johnson 在美国编剧工会东部的访谈中说明，他先从整体形状和叙事序列思考，逐渐放大到细节，正式写正文是后面的工作。他还说明，该片剧本在与 Netflix 达成交易前已经完成。因此，这是创作者的工作方法实例，不能称为 Netflix 强制开发规范。[WGA East：Rian Johnson 访谈](https://www.wgaeast.org/onwriting/episode-100-rian-johnson-glass-onion-a-knives-out-mystery/)

这对产品的直接启发是：长片需要让作者和 Agent 看见“整片怎样组织”，再逐步展开场景。仅有一个自由文本总纲和一条平铺场景列表，难以明确管理这种逐层细化。

另抽查了公开的《玻璃洋葱》剧本：页面以场景标题、动作和对白组织。场景正文的格式与创作时的结构规划属于不同层面。[《玻璃洋葱》剧本 PDF](https://jwlfyc-public-us-east-1.s3.amazonaws.com/1671199094510-go-screenplay_clean_wga48.pdf)

### 3.2 Netflix 剧集案例：《怪奇物语》

Duffer 兄弟的课程公开目录包含两阶段大纲、主要故事线、节拍拆解、故事线交织与篇幅估计；本次只依据公开课程介绍，没有将付费课程未读内容作为证据。[MasterClass：Writing Your Story Outline](https://www.masterclass.com/classes/the-duffer-brothers-teach-developing-an-original-tv-series/chapters/writing-your-story-outline)

Netflix 官方采访还记录了他们在第四季反馈后重新修订第五季大纲的过程。这说明结构可以随着已有作品和反馈调整。[Netflix Tudum：Duffer 兄弟谈第五季](https://www.netflix.com/tudum/articles/duffer-brothers-stranger-things-season-5-wgfest-interview)

对系统的启发：剧集需要全剧／当前季与本集两个观察尺度，允许先有整体方向、细写当前集，再调整后续安排；一集内部也可以组织幕或段落、交织多条故事线。

### 3.3 HBO 剧集案例：《继承之战》

Jesse Armstrong 在 WGA East 访谈中说，编剧室的重要工作之一是弄清这一季走向什么结局；他还会整理每日讨论，维护持续演进的文档。[WGA East：Jesse Armstrong 访谈](https://www.wgaeast.org/onwriting/episode-107-jesse-armstrong-succession/)

这支持“先有较大范围的方向，再组织各集与场景”的流程。它没有证明 HBO 统一要求某个幕数，也不意味着所有剧集必须在开写前锁死全剧结尾。

### 3.4 HBO 编剧的方法与剧本文档

《切尔诺贝利》编剧 Craig Mazin 在 Scriptnotes 的电影写作讲解中，强调人物与核心戏剧问题如何推动结构，并反对机械追随固定页码的结构模板。这是他的创作观点，不应升级成普遍规则。[Scriptnotes 403：How to Write a Movie](https://johnaugust.com/2019/scriptnotes-ep-403-how-to-write-a-movie-transcript)

本次也抽查了《切尔诺贝利》第 1 集的公开剧本副本，正文以场景展开。HBO 原剧本页面当前未能读取，所以采用可访问的原始剧本副本作格式样本，不把转载站的解说当作 HBO 要求。[《切尔诺贝利》第 1 集剧本 PDF，Script Slug 托管](https://assets.scriptslug.com/live/pdf/scripts/chernobyl-101-11-23-45-2019.pdf)

### 3.5 叙事中的幕与电视播出的幕间断点

传统电视编剧中的 Act Break 还可能对应广告间断，稿件会显式标记幕结束。Final Draft 的格式说明指出，部分 HBO 试播集样稿没有显式分幕标题，但仍有叙事结构。[Final Draft：Television Script Formatting](https://www.finaldraft.com/blog/how-to-format-television-scripts)

这是对具体样稿与写作惯例的说明。平台商业模式会变化，不能从“流媒体”或“HBO”标签直接推导当前每个项目的广告安排或交付格式。

## 四、用一个原创例子区分幕、段落和场

以下是解释层级的假设示例，不是对用户作品的新增设定：

```text
全片：主角突破后抵达未来，寻找失踪同伴
└─ 第二幕：追查同伴去向
   ├─ 段落 A：潜入档案馆取得记录
   │  ├─ 场 12：城门外，从守卫口中得知档案已被封存
   │  ├─ 场 13：客栈，决定借庆典混入档案馆
   │  ├─ 场 14：档案馆，拿到被篡改的记录
   │  └─ 场 15：巷口，发现同伴可能参与了篡改
   └─ 段落 B：带着新的怀疑寻找同伴
      └─ ……
```

“追查同伴”是较大的故事发展；“潜入档案馆取记录”是一个有行动与结果的叙事段落；场景负责把它具体表现出来。段落结束时的新信息，引出下一段。

上面的场数只是示意。不能以每四场、每十分钟或每次模型输出作为固定分段标准。

## 五、对当前实现的补充判断

本轮核查了当前结构定义：

- `DeliveryUnit` 内直接保存 `summary` 和 `scenes`。
- `Scene` 有场景目的、进入／离开状态、故事顺序和故事线关联。
- 没有明确的 Act／Sequence 对象及场景所属幕／段落关系。
- 自由文本大纲可以写幕标题，但无法据此可靠选择“第二幕”作为 Agent 的稳定操作范围。
- 交付导出中单篇单元的 `kind: 'sequence'` 只是导出标签，不能证明编辑器已经有叙事序列层。

依据：[结构定义](/Users/yang/Desktop/code/movie/a-22/packages/script/src/schema.ts:18)、[交付转换](/Users/yang/Desktop/code/movie/a-22/packages/script/src/exporters.ts:34)。

因此，对“当前是否已经支持分幕／分段”的准确回答是：**可以写在大纲文本里，但尚无明确的结构化组织和按结构委托能力。**

对于短小作品，直接从较详细的大纲展开分场可以够用。对于长片和复杂单集，缺少可追踪的中间层，会使规划、分批生成、调整顺序和检查覆盖更困难。这属于本产品的工程判断，不是行业强制标准。

## 六、建议的产品流程

### 6.1 仍然保留四个主页面

| 页面 | 建议承载 |
| --- | --- |
| 全案蓝图 | 构想、主题／问题、人物、规则、风格和篇幅；不要求生成整片详细结构 |
| 故事大纲 | 全片总纲，以及可展开的幕／叙事段落；剧集另有分集安排与当前集结构 |
| 分场规划 | 按段落查看和组织场景，检查每段是否实现其叙事目的 |
| 剧本写作 | 按场展开、按段审阅，再做全片／全集检查和修订 |

电影的展开顺序更准确地表达为：

**全案蓝图 → 全片故事大纲〔整体走向、幕／段落〕→ 按段展开分场 → 逐场正文 → 整体修订。**

幕和段落可以在一份大纲中由 AI 一并提出，不必连续点击多个“生成”才能继续。短片允许省略不必要的层级。复杂作品则可以增加结构细度。

### 6.2 一次输出多少

建议把“轻量规划”和“详细展开”区分开：

- 一次可以生成全片总纲与简短的结构目录，让作者看清全貌。
- 每段只需名称、简要事件与结果；有助于创作时再补充涉及的人物线和篇幅预估。
- 详细分场按选定段落生成；正文按场或小批次生成。
- 不要求同一次回复包含完整蓝图、全部段落、几十场规划和所有对白。

这些是系统默认生成策略，不是让作者新增一堆手填项目。用户可以直接说“先展开这一段”“调整第二幕”“写到这一段结束”。

### 6.3 Agent 怎样使用这一层

1. 读取全片方向、当前幕／段落目标、已采用的前文和相关人物资料。
2. 判断本段是否已有可用分场；需要时在授权范围内补充。
3. 按场生成正文，保持前场结果与本段落点一致。
4. 段落完成后检查本段是否产生预期推进，再处理下一段。
5. 全部约定段落完成后，检查整片铺垫与兑现、人物发展、篇幅和遗漏。
6. 交付初稿及剩余事项，作者决定采用和后续修订。

模型请求的批次与叙事结构不必一一对应：一个段落可用多次调用完成；一次规划也可覆盖几个短段落。结构决定创作意图，输出预算决定分几次执行。

### 6.4 最小实现边界

如果后续实施，建议只补足这些能力：

- 在现有大纲中保存有顺序、有稳定标识的结构分组，支持幕与段落；层级允许省略。
- 场景与结构分组建立明确关联，并保持既有场景与正文标识。
- 大纲、分场、聊天、Agent 使用同一份关系，能准确选择某幕／某段，不靠标题猜范围。
- 调整结构时保留已有正文，只提示受影响内容；已有作品可由 AI 提出分组，作者采用。
- 新作品由 AI 提议结构；旧作品没有分组时仍能继续创作。

如果只在提示词里补一句“请按三幕创作”，或只把幕名写入一个长文本框，仍不足以支撑稳定的按幕委托。反过来，也无需现在加入独立的分幕主页面、复杂节奏图或固定八段必填表。

## 七、对前一份计划的修订

保留先前关于目标错位、上下文、单元剧范围和分批生成的修复项。在第 5 项“长篇委托”和第 6 项“形式适配”中，明确加入：

> 长片需要可操作的幕／叙事段落组织，让全片大纲、分场、正文与 Agent 委托范围保持关联；具体采用几幕、几段由作品决定。

先修复会错集、漏读依据等基础问题，再补这一最小结构层；不要以“现有代码没有”为理由否认它的价值，也不要因此把四页扩展成大量强制工序。

验收可用一部包含若干叙事段落的机械样稿：指定第二段生成分场，采用后各场归属正确；委托写第二段时仅写相关场景、仍能读取必要前文；重排或改名不丢失正文；旧项目无分组时照常使用。之后再以真实长片进行创作质量验收。

**最终建议：我们应支持分幕和分段，并将它们整合进大纲与分场。三幕、八序列等方法可选，系统负责把已经选择的结构贯彻到后续写作。**
