## 原审查结论

系统已有重复建设，但不能按页面名称相近、文件多或 Modal 数量多直接删除。主要问题集中在：新旧生成执行链并存、同一项目资产有两套编辑入口、同一生成任务有两套参数与参考选择、退役功能仍在设置与说明中出现，以及能力定义分散。最先应统一实际操作责任，再清理失效入口，最后拆分大文件和整理兼容层。全面重写或强制所有功能进入一个画布会制造更多迁移问题。

判定标准：相同目标、相同数据、相同修改动作，却有两套独立实现或两套互不说明的状态，属于冗余。不同范围或生命周期，如剧本原稿与制片快照、全局资产与项目实例、生成成功与正式采用，属于必要边界。

## 冗余问题与收敛建议

### F01 新工作台接管执行但旧生图入口仍可达

**确认，最高优先级。** `src/server/generation/routes.ts:97-101` 的 `registerGenerationBoundary` 拦截旧图片/视频 POST，要求固定计划。但 `ImageGen.tsx:119`、`bible/AssetDetailView.tsx:422` 仍直接调用 `generateAIImage`；`ProductionAssets.tsx:99-100,209` 的批量按钮接 `useProductionAssetBoardBatch.ts:396` 同一路径。场次顶栏 `Storyboard.tsx:816-821` 仍进入 `useStoryboardBoardBatchAgent`，其结构整理后还有 `runStoryboardSceneVisualPages → generateAIImage`（:376、1012、1492）。`apps/worker/src/production-media-worker.ts` 也仍向旧图片代理提交。配置页 `ComfyGatewaySettings.tsx:70-76` 的测试任务经 `comfyGatewayClient` 提交同一被拦截路径，因此问题还覆盖服务测试。

因此至少在这些 API 生成分支会遇到新边界拒绝；测试模式外部回填是另一分支，不能概括为所有方式都失效。旧 hooks 数量不等于全部仍可触发，其他引用需逐条确定。

建议：先建立“供应商 × 操作 × 输入能力 × 旧入口 × 新适配”覆盖表。新 catalog 当前只包含 Comfy 和指定 KIE，旧 `ai.ts:283/305/330` 仍有 Gemini/OpenAI/豆包分支；不能只换按钮而丢掉原有适配能力。未有新适配的操作须明确待接通或提供受同一授权边界保护的兼容承接。为每个现役图片/视频入口建立调用表；项目目标创建 GenerationTask/Plan，批量转批次。全局/无项目生图不能硬塞随机项目，目前 GenerationTarget 要求 projectId，应先明确全局/临时任务归属及结果导入协议，再迁移独立生图。保留旧任务查询、媒体和导入；不能简单放开边界，也不能简单隐藏有效业务入口。完成标准：所有可见“生成”按钮都能预检、执行或明确说明未支持，不在点击后才以旧接口错误失败。

### F02 摄影棚仍维护第二套参考与模型设置

**确认，最高优先级。** `Studio.tsx:1450-1510` 在新工作台按钮下仍挂载 `StudioGenerationTargetPicker` 与 `StudioReferenceControlPanel`，允许修改方式、资产、首尾帧、历史图片/视频/音频引用。新工作台入口 `Studio.tsx:1245` 主要传目标与 operation；工作台/引擎维护独立任务草稿，不能把旧面板的本地选择视为新任务最终输入。

建议：摄影棚保留选择镜头/片段、导入、媒体历史与声音剪辑；目标选择仍通过 `manualStudioTarget` 影响新工作台 kind/shotIds，不能整个删除或改只读。生成方式与本次参考/采样参数以工作台为唯一修改位置。对现有旧草稿显式显示“导入旧选择”的差异预览，一次迁移，不静默覆盖工作台人工选择。仍供历史任务解释的设置改只读。需要验证具体字段的正式持久来源后再决定迁移，不能一次删除整个折叠区。

### F03 同一项目资产有两套详情与更新语义

### F05 规划选定方案与实际执行初始化没有完整衔接

### F08 AI 入口的作用域和任务状态需要统一解释

**部分重叠，中优先级，不能粗暴合并。** 全站助手、写作 Durable 对话、互动 AI 抽屉、生成参数建议都是现役入口，但分别承担跨模块交接、文学创作、互动图、媒体参数。旧 `ScriptAssistant` 仍被 `ScriptWorkspace.tsx:1038-1050` 用于历史、Durable 未覆盖或带专项 reviewSource 的任务，既可 API 执行也可外部回填；`ScriptAgent.tsx` 则没有检出的静态入边。

建议：统一“当前在操作哪个项目/对象、建议还是执行、改动落在哪里”的显示与能力路由；业务执行器按领域保留。先清理无入口旧 UI，再评估旧 agent-runs 写入口和历史数据，不因新 Durable 上线直接删全部旧任务记录。

### F09 导航定义分散与操作返回语义不准确

**具体误标确认；层级过载降为风险。** 全局项目导航、场次步骤、对象检查器的职责不同；`ProductionWorkflowGuide.tsx:15,20,32,35,44-47` 已默认折叠，并在场次页隐藏另一套编号和前后步骤，不能声称它们仍全部同时铺开。仍有多份导航定义需同步维护。

建议：入口显式提供返回上下文和对象名称；统一导航定义与深链接。全局选模块、项目栏选阶段、场次栏选本场步骤、检查器处理对象；已有折叠措施保留。不新增“极速/专业”总开关解决这些问题。

### F10 候选与采用交互实现较多

**确认实现分散，抽象程度需控制。** 资产参考、视觉板、宫格、视频、文字拆解、互动计划各有 Review 组件；图片/视频结果还在工作台和所属阶段展示。多个位置看同一结果是合理投影，若各自算 adopted/stale/pending 才是危险冗余。前轮已修复历史采用与旧候选计数问题，不能把这一修复当成全系统状态统一完成。

建议：共用来源/版本/当前采用状态和基础候选查看 UI；保留领域专属校验与正式采用命令。文本计划采用、整页宫格采用、视频剪辑采用不能共用一个无语义的 `approve()`。

### F11 有少量静态无入口组件及大文件集中维护负担

**候选清理，中低优先级。** 静态相对导入扫描发现 `StoryboardHeader.tsx`、`ScriptAgent.tsx`、`ScriptContextPanel.tsx`、`StoryIncubatorModal.tsx`、`StoryTreeNavigator.tsx` 没有入边；入口 main 文件另行排除。这只能作为候选，还须核对字符串加载、测试、外部工具和存量功能。另有“有导入但实际不可达”类别：`Storyboard.tsx:1258` 外层要求 `!isDirectorProductionRoute`，:1259 内层的 true 分支却要求相反条件，恒不可达；当前 App 仅挂载 `/production/storyboard`，整个旧部门视图也不能因此算作现役桌面模块。组件清理与 Operator/worker/CLI 服务退役必须分开，先核对外部合同和历史查询。

源码行数：`ProductionSourceOverviewWorkspace` 2030、`Studio` 1790、`Storyboard` 1714、`InteractiveGraphWorkspace` 1679、`PromptEditorModal` 1628、`Settings` 1515。行数提示职责集中，不证明功能多余。建议按用户动作与数据责任拆分，不先做目录搬家；保留功能和测试证据。

### F12 相似目录及任务系统不能一刀切合并

**必要边界与局部兼容债务。** `apps/web/src/App.tsx` 仅重导出 `src/App`，`apps/api/src/index.ts` 启动同一 server，部分 clients 为重导出。这不是两套独立应用。GenerationExecution、供应商任务、ProductionRun、剧本 Durable run 的生命周期不同，不能为统一名词合成一个万能表。

建议：标明实际所有权与依赖方向；新代码只能在指定所有者实现，别再复制适配。共享取消、错误分类、幂等/日志等机制前，先确认事务和恢复语义相同。旧查询兼容层随调用清单逐步收缩。

### F13 全局音色接口库与正式角色配音脱节

**确认，高优先级。** `GlobalVoiceLibrary.tsx:7,116-120` 读写 `voiceProfiles` 并按任意 URL、headers、bodyTemplate 联调；全仓仅该组件与 useGlobalStore 消费 voiceProfiles。`CharacterVoiceSettings.tsx:26,35-37` 和 `useStudioAI.ts:933-936` 则走 `character.voiceSettings + AIConfig + audioGen`。用户在“音色库”配置成功并不意味着能在角色配音中选到。

建议：首先明确旧库是自定义接口档案还是可复用音色目录。统一服务配置后，把能表达的旧档案映射为音色预设，保留无法映射的原始模板并标注用途；角色绑定与单句表演参数继续分开。TTS/BGM/SFX 尚不属于 GenerationOperation，不能为了统一 UI 强塞图片/视频工作台。

## 必须保留的功能边界

| --- | --- | --- |

| 全局资产与项目资产 | 复用模板与作品实例/状态不同 | 媒体查看、导入、正式项目详情 |

| 角色资料板与纯净参考图 | 人读信息与模型视觉输入不同 | 图像候选展示、来源与采用 |
| 整场宫格与单元宫格 | 创作总览与单次模型容量不同 | 参考查看、映射、来源追踪 |
| 互动图与生成画布 | 叙事条件边与素材依赖边不同 | Canvas 外壳、工具栏、基础排版 |
| 互动制片绑定与摄影棚 | 播放绑定与媒体制作不同 | 跳转、素材选择和媒体状态 |

## 建议的唯一责任划分

1. 写作拥有文学事实、大纲、分场、正文及文学审阅。
2. 制片拥有导入快照、项目视觉资产、场次设计、镜头、视频单元与最终剪辑。
3. 互动拥有节点、选择、状态、绑定、运行和试玩。
4. 当前生成服务拥有图片/视频任务草稿、固定计划、授权、执行和候选产物；正式采用归相应领域命令。声音任务保留专用流程，后续只在合同明确后共用基础机制。
5. 全局资源拥有跨项目资产模板、音色、技能与外部服务配置。
6. UI 可以多处定位同一对象，但同一字段只有一个编辑合同，同一动作只有一个服务所有者。

## 迁移前置条件

- SQLite 不是全部数据：`useGlobalStore.ts:59-116` 将全局资产、voiceProfiles 和 BGM 设置保存在浏览器 `global-storage`；`useEpisodeFilmExport.ts:179-181` 仍据此解析音轨引用。盘点数据库、localStorage/sessionStorage、媒体文件与历史草稿，保留 ID 和 linkedAssetId。
- 为概念图、基础参考图、资料板、纯净参考、变体、已采用媒体列字段映射；不以“都有图片”为由相互覆盖。
- 保留来源版本、人工选择与锁定、旧任务查询、候选与采用审计。迁移须可重入、提供回执与回退，先在隔离副本验证。
- 外部包 `baseDeliveryId` 不是内部 revision；selected 包省略对象不表示删除。外部完整包导入仍是未实现能力，不混入本次删冗余的完成声明。
- 退役 UI、退役写 API、删除历史记录是三个不同动作。Operator capabilities、worker/CLI、测试、深链接与历史读取需分别确认替代路径。
- 验收不仅是生成：分镜预演导出、完整视频/连续完成场次导出、声音与字幕、互动固定 runtime build HTML 导出都须保留原领域合同与保存失败保护。
