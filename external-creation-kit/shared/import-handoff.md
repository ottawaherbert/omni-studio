# 交回 Omni Studio 时的检查与映射

这是回填实施说明，不是已实现的自动导入器。格式版本为外部交换 v1。系统原生 `script.v1`、`script-delivery.v2` 与互动保存对象还包含内部身份和版本约束，不能直接用外部文件覆盖。

## 检查顺序

1. 保留收到的原包，运行校验器。确认 projectId、交付范围、基准版本、文件清单、完整正文、ID 和引用。对 selected 包先获得完整基准；对缺文件、未决事项或检查截断不宣称全项目通过。
2. 通读剧情与试玩路径。检查人物知识、道具、时空、选择后果、汇合后的记忆和结局兑现。离线图检查只证明抽象状态图的性质，不证明自然语言或实际系统播放器的表现。
3. 生成导入预览：新建/修改/删除对象、完整正文差异、原对象对应关系、受影响制作成果与未解决冲突。沿用用户已授权的作品与修改范围，按 [外部 Agent 操作手册](../../doc/agent-guide.md) 的原生接口写入；归属或覆盖范围不明才澄清。入口不足时如实记录，不直接改业务数据库。
4. 回读系统保存的数据，核对场数、ID 映射、正文与分支。实际试玩代表路径和条件组合，再验证能进入制片。保留导入回执，记录外部 deliveryId 与实际系统版本的对应关系。

## 映射原则

| 外部数据 | 系统对应方向 |
| --- | --- |
| bible 人物、事实、profile、units | 作者项目的人物、事实、作品形态及单元；根据已有项目创建或沿用内部 ID |
| scenes / blocks | 作者场次与正文块；秒数转换为毫秒；对白 speakerId 先做人物映射 |
| 作者正文完成后 | 从作者项目生成系统自己的制片交付快照；不把外部 deliveryId 冒充 sourceRevision |
| interactive variables | 有类型和默认值的状态变量；外部 integer 对应系统 number 时保留整数取值约束 |
| structured conditions / effects | 系统 PredicateAST / StateEffectAST 可表达的子集，经实际验证后转换 |
| nodes / edges / endings / chapters | 互动图与章节、结局约定；实际运行能力仍需系统验收 |
| sceneIds / mediaPlan | 先建立剧本映射与待制片计划；视频制作后再绑定真实媒体，不伪造 URL、镜头版本或资源引用 |

交换文件的编号是外部稳定身份。导入层需要保存外部 ID → 系统 ID 的对应表。已有项目可能有自己的 ID；未经检查不能强行替换。内部修订号、时间戳、审批、任务、运行状态与媒体版本由系统生成。

## 局部修订与已有制作成果

`baseDeliveryId` 仅用于辨识外部基准，不提供系统并发保护。真正保存前仍要读取系统当前版本并按现有版本校验保存，发现并行改动就生成冲突预览。

`scope.kind=selected` 的省略对象保持原样；即使完整快照少了对象，也不能静默删除。只有 `changes.deletedIds` 加上明确预览后的实际删除操作才表示删除。`interactive: null` 表示本包不含互动文件，不表示清空已有互动项目。

正文改变后保留现有分镜、媒体和绑定，标注需复核的依赖。不能承诺所有画面仍可直接复用，也不能为方便导入删除制作成果。尚未处理的冲突和未完成验收留在回执中。
